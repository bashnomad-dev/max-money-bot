# Чеклист передачи в прод (тест → боевой)

Статус на старте: всё работает на **тестовых аккаунтах** (тестовый whitelist-пользователь,
бот `@Finans_stroy_bot`, OpenRouter на аккаунте вендора, таблица Евгения с тестовым мусором).

## 0. Решение: модель владения
- [ ] **Managed** — инфра (VPS, ключи OpenRouter, бот) остаётся на вендоре, обслуживание за плату. Евгению проще, но он завязан на вендора.
- [ ] **Полная передача** — всё на аккаунтах Евгения, он автономен.

Выбор влияет на пункты ниже (что переоформлять).

## A. Запросить у Евгения / решить с ним
- [ ] **MAX user_id** — Евгений пишет боту любое сообщение, id появится в логах (`journalctl -u maxbot`) → в `ALLOWED_USER_IDS`. Сейчас тестовый `158102131`.
- [ ] **user_id продавцов**, если им тоже писать боту.
- [ ] **Бот:** регистрируем продакшн-бота на его ООО (реквизиты ООО для https://dev.max.ru → новый `MAX_BOT_TOKEN`) **или** оставляем `@Finans_stroy_bot`.
- [ ] **Боевая таблица:** подтвердить, какая «настоящая», или дать добро на чистую новую. Кто ещё имеет к ней доступ (бухгалтер?).
- [ ] **Timeweb VPS:** IP + SSH-доступ (или Евгений заводит Ubuntu 24.04 и передаёт доступ). Кто платит за VPS.
- [ ] **Оплата OpenRouter** (предоплата в USD): кто держит и пополняет аккаунт. При managed — вендор.
- [ ] **Категории расходов** Евгения (аренда, зарплата, налоги, доставка…) — дополнить лист «Категории».
- [ ] **Подтвердить настройки:** названия точек (Зинино/Кармалы точь-в-точь), `LARGE_AMOUNT_THRESHOLD_RUB=150000`, `DAILY_REPORT_TIME=21:00`, нужен ли `OPS_PIN` на `/отмени` и `/правка` (и какой).

## B. Сделать вместе (сессия передачи, ~1 час)
- [ ] Евгений пишет `/старт` → поймать его user_id → в `ALLOWED_USER_IDS` → рестарт.
- [ ] `/привязать <sheet_id>` → `/настройка` на **чистой** таблице (импорт 4883 SKU).
- [ ] Прогнать 5–6 **реальных** операций его словами: продажа, закупка, возврат, расход, `/остаток`, `отчёт за месяц`.
- [ ] По ходу — добавить **алиасы** частых товаров в лист «Товары» (напр. «цемент» → нужный канон), чтобы бот не переспрашивал.
- [ ] **Проверить голос** — Евгений диктует голосовое, GigaAM должен распознать его речь/темп (ffmpeg на VPS обязателен).
- [ ] Показать русские команды, `/отмени`, `/правка`, `/пересчёт`, `/сегодня`. Правило: одна операция за раз, до 120 сек.

## C. Сделать самому (вендор)
- [ ] Поднять VPS: `git clone … && bash deploy/setup-vps.sh`, залить `.env` + `secrets/service-account.json`, `systemctl start maxbot`.
- [ ] cron-бэкап Sheets (строка в `deploy/setup-vps.sh` / RUNBOOK).
- [ ] **Почистить тестовые данные** перед боевым стартом. Два пути:
  - **Чистая новая таблица (рекомендую):** создать пустую, расшарить на сервисный аккаунт, прописать `DEFAULT_SHEET_ID`, `/настройка` → импорт 4883 SKU. Никакого риска зацепить реальные данные.
  - **Сброс журналов в текущей:** `python -m scripts.reset_ledger <SHEET_ID>` — сухой прогон (покажет, что удалит); `CONFIRM=YES python -m scripts.reset_ledger <SHEET_ID>` — очистит «Движение денег/товаров/Остатки» (справочники и прайс остаются), предварительно сделав .xlsx-бэкап. Потом `/пересчёт`.
- [ ] **Проверить OpenRouter с RU-IP** на самом VPS (один тестовый парс через `python -m scripts.cli "..."`).
- [ ] Включить `LLM_BACKEND_FALLBACK=gigachat` (резерв на падение OpenRouter) и проверить ветку фолбэка.
- [ ] Удалить тестовую e2e-таблицу.
- [ ] Памятка Евгению (как пользоваться) + мониторинг логов первую неделю.

| Переменная | Сейчас (тест) | Прод |

| `ALLOWED_USER_IDS` | `158102131` | MAX user_id Евгения (+ продавцы) |
