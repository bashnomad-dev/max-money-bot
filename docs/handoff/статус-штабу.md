# Статус штабу: тест-неделя Евгения (подключение + деплой)

Дата: 2026-06-11. Ветка: `fix/demo-stt-parsing` (коммиты `012a95a`, `b2c8a32`).

## Среда (важно — контекст от владельца)
- Бот **уже задеплоен на сервере владельца** (наш/его сервер), там его **тестовые данные**, поставлены под тест.
- Таблица — та же, что на ДЕМО.
- Доступ к серверу есть у владельца. Из агентской песочницы shell-доступа к этому серверу **нет** — деплой руками агент выполнить не может, только отдаёт команды.

## Готово (код)
- Упрощение под «записную книжку»: остатки off, каталог не принуждаем, автоотчёт 21:00 off, дефолт точки = Зинино, few-shot на фразах ДЕМО, фикс зацикливания отчёта.
- Многопользователь: колонка «Автор» (MAX user_id), `/setup` мигрирует старую таблицу.
- STT: авто-фолбэк; число-нормализация не нужна (разобрали лог ДЕМО — числа распознаются, мисхиры имён → пишем как есть).
- 105 тестов зелёные.

## БЛОКЕР подключения Евгения
- От Евгения получена **только часть данных** — нужно уточнить, что именно недостаёт (вероятно: его MAX user_id и/или он ещё не добавил/не открыл бота у себя).
- Важно: если оставить `ALLOWED_USER_IDS` пустым — Евгений зайдёт **без user_id**, его «часть» не блокирует тест. Тогда подключение = он просто пишет боту.
- Владелец вчера вечером сам хотел подключить Евгения.

## Что нужно сделать на сервере (владелец/штаб, доступ есть)
```
git fetch && git checkout fix/demo-stt-parsing && git pull
printf '\nENABLE_STOCK_TRACKING=false\nENFORCE_PRODUCT_CANONICALIZATION=false\nDAILY_REPORT_ENABLED=false\n' >> .env
systemctl restart <сервис>
```
Затем один раз `/setup` боту (миграция колонки «Автор»).
