# Бэклог (отложено, не делать без апрува)

Идеи и фичи, отложенные ради чистой тест-недели Евгения. Не удалять — обсудить после теста.

## Дополнительные «склады»-вкладки (фуры до оприходования)
**Источник:** живой диалог ДЕМО (11.06), подтверждено владельцем как новая фича.

**Суть:** у Евгения на базе стоят фуры от разных поставщиков, товар ещё НЕ оприходован в магазин,
но с него уже идут продажи. Он хочет несколько отдельных «складов»/вкладок (условно склад 1–5,
по поставщику: «Максим», «Петя», «Дима»), куда голосом скидывает позиции: «вкладка 1, такая доска 100 штук».
Потом смотрит по каждой вкладке, сколько с этого поставщика отгружено за день. По мере приёмки —
переносит в магазин.

**Почему не сейчас:** это расширение модели точек/складов и нового namespace операций —
архитектурное изменение, требует апрува и не успеть к тест-неделе. Сейчас точки = Зинино/Кармалы.

**Связано:** остатки владельцу не нужны (ведёт в 1С) — см. флаг `ENABLE_STOCK_TRACKING`.

## STT: мисхиры названий/брендов (НЕ числа)
Разбор расшифровки ДЕМО (`docs/intake/ ДЕМО-фид бэк/скопированные с бота + текст расшифрвка.txt`):
числа STT распознал корректно (18 тысяч, 50000, 150 тысяч, 276 штук — без порчи), словесные числа
конвертирует LLM-парсер. Нормализация чисел на STT-уровне НЕ нужна.

Реальные ошибки STT — мисхиры имён: «калиповая»→липовая, «сот а»→«сорт А», «в Лила»→Леруа,
«катафал»→«Катав» (бренд из прайса), «бус»→брус. На тест-неделю митигируется записью товара
как надиктовано (канонизация отключена, владелец правит сам).

Глубокий фикс: доменный словарь-подсказка для STT или фаззи-привязка распознанного к прайсу
(это и есть отключённая на тест-неделю канонизация — см. `ENFORCE_PRODUCT_CANONICALIZATION`).

## Мульти-операция в одной диктовке
«Продал …, отгрузил Алмазу …, Ильдар цемент …, краску в долг» — несколько операций в одном
сообщении. Сейчас модель берёт одну (tool_choice — один tool). Нужна декомпозиция в пайплайне
(несколько tool-call / цикл). Оценить после теста, если кейс частый.
