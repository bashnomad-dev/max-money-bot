[01.06.2026 22:06] Дмитрий Дмитрий: # Max Finance Bot

Телеграм-подобный бот на платформе MAX (библиотека maxapi) для учёта финансов и материалов строительной компании. Сообщения пользователя разбираются через GigaChat, записи сохраняются в Google Таблицу, по расписанию рассылается ежедневный отчёт по движению денег.

---

## Что умеет бот

1. Текстовые операции 
   Пользователь пишет свободным языком (например: приход/расход денег, закупка материалов, отгрузка). GigaChat возвращает структурированный JSON; бот записывает строку в нужный лист таблицы и отвечает подтверждением.

2. Две таблицы в Google Sheets 
   - лист «Движение денег» — приход/расход, сумма, категория, контрагент, объект, способ оплаты;  
   - лист «Материалы и работы» — тип (получено/отгружено/работа), объект, наименование, количество, единица, комментарий.

3. Контекст чата 
   Для полей вроде объекта, способа оплаты и контрагента бот подставляет значения из последнего удачного сообщения в этом чате, если в новом сообщении их не указали.

4. Голосовые сообщения 
   Голос скачивается, через ffmpeg конвертируется в WAV 16 kHz mono, распознаётся моделью GigaAM (gigaam), затем текст обрабатывается так же, как обычное сообщение. Нужен установленный ffmpeg в PATH.

5. Отчёты по запросу 
   Фразы вроде «отчёт за месяц» / «отчёт за квартал» / «отчёт за год» запускают диалог: бот спрашивает период (например, «текущий месяц», «январь 2026», «2025 год»). Отчёт строится по листу «Движение денег»: приход, расход, итог, число операций, топ-3 объектов по обороту.

6. Автоотчёт по расписанию 
   В заданное время (по Москве) в все известные чаты отправляется краткий отчёт за сегодня (приход, расход, итог). Список чатов накапливается в файле known_chats.json (чат попадает туда после первого входящего сообщения).

---

## Требования

- Python 3 (рекомендуется версия, под которую создано виртуальное окружение проекта).
- Аккаунт и ключи: MAX (токен бота), GigaChat (API key), Google Cloud service account и доступ к таблице.
- ffmpeg — для голосовых сообщений.
- Достаточно CPU/RAM для загрузки модели GigaAM при первом голосовом сообщении.

## Установка

Из каталога max-finance-bot:
python -m venv .venv

Windows (PowerShell):
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

Linux / macOS:
source .venv/bin/activate
pip install -r requirements.txt

Скопируйте .env.example в .env и заполните переменные (см. ниже). Положите файл ключа сервисного аккаунта Google (по умолчанию credentials.json) в тот же каталог, что и main.py, либо укажите путь в GOOGLE_CREDENTIALS_FILE.

  Для отчётов (reports.py) в первой строке (заголовки) должны быть столбцы с именами «Дата», «Тип операции», «Сумма (₽)», «Объект/проект» (остальные колонки могут быть; важно совпадение этих заголовков).

   В заданное время (по Москве) в все известные чаты отправляется краткий отчёт за сегодня (приход, расход, итог). Список чатов накапливается в файле known_chats.json (чат попадает туда после первого входящего сообщения).

## Google Таблица

В книге должны быть листы с точными именами:

- «Движение денег» — колонки для записи: дата, время, тип, сумма, описание, категория, контрагент, проект, способ оплаты (как в `sheets.py`).  
  Для отчётов (`reports.py`) в первой строке (заголовки) должны быть столбцы с именами «Дата», «Тип операции», «Сумма (₽)», «Объект/проект» (остальные колонки могут быть; важно совпадение этих заголовков).

- «Материалы и работы» — дата, время, тип, объект, наименование, количество, ед. изм., комментарий.

Сервисному аккаунту выдайте доступ на редактирование таблицы.

## Возможные проблемы

- «MAX_BOT_TOKEN is not set» — нет или пустой .env.  
- Ошибка записи в Sheets — проверьте GOOGLE_SHEETS_ID, путь к credentials.json, права сервисного аккаунта и названия листов/заголовков.  
- Голос не распознаётся — установите ffmpeg, проверьте PATH; на Windows при сбоях torch иногда отключают oneDNN (см. комментарии в `voice.py`).  
- Пустой или странный отчёт — убедитесь, что даты в таблице в формате ДД.ММ.ГГГГ и заголовки колонок совпадают с ожидаемыми в reports.py.
