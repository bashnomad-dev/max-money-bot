# Intake: Евгений (Евгений Йога)

Полные исходные материалы по реальному клиенту. Этот документ — TL;DR для быстрого возврата.

## Кто клиент

**Имя:** Евгений (никнейм в чате — "Евгений Йога").
**Бизнес:** строительный рынок / складская база ("Магазин Зинино"). Не классический ритейл с прилавком — **B2B-склад с розницей**.
**Работает один:** после случая с воровством сотрудников 3-4 года назад разогнал продавцов и тащит всё сам. Прямая цитата: «Я рву себе жопу в любое свободное время».
**Юридическая структура:** ИП/ООО (множественные: «квартал по 3 организациям закрываю»).
**Источник денег:** постоянные клиенты по телефону, крупные единичные отгрузки. Прямая цитата: «Один человек позвонит — купит на миллион, и я его отгружу».

## Реальный домен

**Не прораб** (как в шаблонном ТЗ из 00-source-spec-DEPRECATED.md). **Не классический розничный магазин.**

Это **оптово-розничная стройбаза**: пиломатериалы (доска, брус, имитация бруса), цемент, метизы и стройматериалы. Топ-8 по продажам 2025 — пиломатериалы (см. `продажи 2025.xlsx`). Основная база — **Магазин Зинино**.

Канал продаж: **телефонные заказы от постоянников + случайная розница на точке**. Цикл сделки короткий. CRM/воронки не нужны и не интересны.

## SKU и справочник

**Справочник есть готовый:** `Прайс 2025.xls` (1.5 МБ, 9793 строки в листе TDSheet — реально 2000-9000 активных SKU). Структура: Номенклатура / Цена (руб.) / Единица измерения.

**Прямая цитата Евгения про объём:** «Больше 2000» позиций в обороте.

**Мёртвый склад:** «Миллион 3-4 [руб.] лежит в мёртвых позициях». Пример: доска 30×100 2 сорта — спрос ушёл после ужесточения техн. надзора.

## Текущий учёт

**НИКАКОЙ систематической системы.** Прямые цитаты Евгения:
- «У меня всё вылетает из башки»
- «Я ничего не записываю»
- «Я просто этот доходов ни уходов не успеваю»
- «Так в голове плюс минус. Баланс есть. Чуйка и всё»
- «Я пытался вести. Но проблема в том, что нужно вносить данные, а я не успеваю. Забываю»

**1С/касса не упоминается** для розницы. Есть бухгалтер «не на розницу» — для отчётности по ИП/ООО.

**Это значит:** дублирования с существующей системой нет. Бот **создаёт учёт с нуля**, не дополняет. Привычки нет — будет забывать.

## Главные боли (по словам самого Евгения)

В порядке убывания. **Учёт денег и материалов — НЕ номер 1!**

1. **БУМАГИ.** Прямая цитата: «Бумаги. Весь учёт. Подписывать документы с контрагентами, договора, составлять, всё вести по порядочку лежать. Это вообще ненавижу».
2. **Сверки с поставщиками/контрагентами** — копятся, делаются ночами.
3. **Счета, акты, отчётности** — выставлять, подписывать, сдавать, хранить.
4. **ЭДО** — «Сложно выписать, загрузить, подписать. Проверить бухгалтер, куда-то пришить».
5. **Один работает** — не успевает разложить товар, делает ночью.
6. **Мёртвый склад на 3-4 млн руб.** заморожен.

**Сам Евгений говорит про бот учёта:** «Я не вижу, как мне эта нейронка поможет никак». Согласие на 99% — потому что Дмитрий настойчиво продаёт и риск бесплатный.

К голосовому учёту относится скептически, но допускает: «Если ты сказал словом в телефон и он куда-то это отнёс и правильно отнёс и не забыл и не перепутал».

## Контекст переговоров

### Конкурент-фрилансер (Дмитрий)
- Уже сделал прототип `max-finance-bot`. Структура: main.py, handlers.py, parser.py, sheets.py, reports.py, scheduler.py, voice.py.
- Стек **полностью российский:** `maxapi` + **GigaChat** + **GigaAM** (Сбер) + Google Sheets + ffmpeg.
- Цена: **11 000 руб бот + 1500/мес обслуживание + 500 руб сервер + ~500 руб API**.
- Срок: **5 дней до пилота**.
- Минус: ТЗ сделал по шаблону «прораб», не разобравшись в реальном домене Евгения (стройбаза).

### Партнёр пользователя (тоже Дмитрий)
- Конкурирует с фрилансером за этого же клиента.
- Предложил Евгению **5 нейросотрудников:** Документы / Почта / Финучёт с голосом / Нейромаркетолог / Нейропродавец.
- Финучёт-голос — **одно из 5 направлений**, не отдельный продукт.
- Цена: **30 000 за бот, 50 000 за первый этап** внедрения.
- Условия: первый этап (тест) **без аванса**, Евгений платит только себестоимость по токенам (~10-15 тыс руб).
- Договорено **99%** что запускаем.

## Что это значит для нашего ТЗ

| Вопрос ревью | Ответ из материалов |
|---|---|
| Стоит ли 1С / касса? | **Нет.** Учёт «в голове». Дублирования не будет. |
| Сколько SKU? | **>2000** (по словам Евгения), 2-9 тыс в прайсе. |
| Есть ли справочник? | **Да** — `Прайс 2025.xls`, готов к импорту. |
| Что планирует диктовать? | Всё (некому больше). Но без привычки — будет забывать. |
| Реальный домен? | **Стройбаза**, оптово-розничная, пиломатериалы + базовая стройка. Магазин Зинино. |
| Multi-tenant? | Single — для Евгения один. |
| Что главное? | **Бумаги, не учёт.** Учёт — вторичная боль. |

**Наш v2.0 ТЗ в целом правильно угадал домен** (магазин стройматериалов), но:
- Канонизация SKU обязательна с импортом из прайса (это уже в v2.0)
- 14 tools и multi-tenant техдолг — overengineering для одного клиента (риск из ревью подтверждается)
- Конкурент за 11k руб делает то же самое за 5 дней (минимум функций) — нужна явная дифференциация
- **Главную боль Евгения (бумаги) бот учёта не решает** — возможно стоит расширить scope или хотя бы признать ограничение

## Открытые вопросы для обсуждения

1. **Конкуренция или дифференциация с фрилансером:** делаем «свой такой же» или премиум-полный пакет?
2. **Стек:** Whisper+Claude (наш v2.0) vs GigaAM+GigaChat (конкурент)? Российские бесплатнее, данные не уходят за рубеж, для клиента критично.
3. **Scope:** ограничиваемся финучётом или сразу пакуем «Документы» из направлений партнёра?
4. **Юрлицо для MAX:** у Евгения есть (3 ООО) — отлично. У нашей стороны — проверить.
5. **Реальная мотивация Евгения** — учёт ему интересен только если «не забудет, не перепутает». Карточки подтверждения становятся ещё важнее.
